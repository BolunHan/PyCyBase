Dual-Interface Design
=====================

The dual-interface pattern binds a C struct to a Cython/Python wrapper:
the *forward* direction (adopting a C handle into a wrapper via
``c_from_header``) is trivial; the *reverse* direction — a C buffer dying
while wrappers are still alive — is where double-frees, null-dereferences,
and use-after-free bugs live. PyCyBase closes that loop with the
``CCPType`` binding family, built on the :doc:`allocator_protocol`
callback system.

Binding Usage
-------------

``CCPType`` is the shared base class for wrappers whose buffer can be
freed by a path other than the wrapper's own ``__dealloc__`` — an external
C owner, a shared destroy API, or another wrapper over the same block.
Inheriting it gives each wrapper a binding state, an automatic unbind, and
header invalidation when the buffer dies.

The whole usage contract is two call-site rules:

1. **Everywhere a ``_new``-like method** inits a dual-interface struct into
   an instance, call ``ccp_bind(&self.header)`` afterward.
2. **Everywhere ``c_from_header``** (or any method creating a wrapper from
   an existing struct instance) is called, call ``ccp_bind`` (the header is
   a block start) or ``ccp_bind_embedded`` (the header is an interior
   pointer — pass the parent block start) afterward.

``c_from_header`` itself never binds — at adoption time it cannot know
which variant applies.

.. code-block:: cython

   cdef class CCPBoundBuffer(CCPType):        # pxd: cdef char* header; cdef bint owner
       def __init__(self, size_t size):
           self.header = <char*> c_ap_alloc(size, AP_DEFAULT_ALLOCATOR)
           if not self.header:
               raise MemoryError()
           self.size = size
           self.owner = True
           self.ccp_bind(&self.header)        # rule 1: after the _new-like init

       @staticmethod
       cdef CCPBoundBuffer c_from_header(char* header, bint owner=False):
           cdef CCPBoundBuffer instance = CCPBoundBuffer.__new__(CCPBoundBuffer)
           instance.header = header
           instance.owner = owner
           instance.size = strlen(header) if header else 0
           return instance                    # NO bind — the caller decides

   # rule 2, at the adoption call sites (caller side):
   #   block start: view  = CCPBoundBuffer.c_from_header(block,   False)
   #                view.ccp_bind(&view.header)
   #   interior:    entry = CCPBoundBuffer.c_from_header(block+i, False)
   #                entry.ccp_bind_embedded(&entry.header, block)

The three binding scenarios covered by ``CCPBoundBuffer``:

.. list-table::
   :header-rows: 1

   * - Scenario
     - Header field holds
     - Bind op
   * - Owned
     - a fresh ap-allocated block start
     - ``ccp_bind`` in ``__init__``
   * - View (not owned)
     - an adopted block start
     - ``ccp_bind`` at the adoption call site
   * - Embedded
     - an interior pointer into a parent block
     - ``ccp_bind_embedded`` with the parent block start

Extra teardown via ``__ccp_dealloc__``
--------------------------------------

When invalidation must reset more than the header field, override the
``cdef void __ccp_dealloc__(self)`` hook. It runs on the DEALLOC pass
**before** the header is nulled, so the override may still deref the
header:

.. code-block:: cython

   cdef void __ccp_dealloc__(self):
       self.size = 0        # reset additional fields beyond the header

The base implementation is a no-op; overrides are detected automatically
at bind time by function-pointer comparison. The hook is armed inside
``ccp_bind`` / ``ccp_bind_embedded`` — not in ``__cinit__``: the subclass
vtab is only installed after the base ``tp_new`` (and its ``__cinit__``)
returns, so ``__cinit__`` cannot yet see an override.

Husk semantics
--------------

A wrapper whose buffer was freed is a **husk**: its header is NULL, its
binding is released, and ``size`` is zeroed by the hook. Every entry point
must NULL-guard — getters degrade (``None`` / ``0`` / ``'NULL'``), setters
raise ``BufferError`` — and ``__dealloc__`` frees only when ``owner``.
Wrappers that were never bound deallocate silently (unbind is idempotent).

Technical Specification
-----------------------

Binding prefix (C side)
^^^^^^^^^^^^^^^^^^^^^^^

The C ops assume a fixed prefix on every bound wrapper — the C
translation of the ``CCPType`` cdef class, generated by Cython:

.. code-block:: c

   typedef struct ccp_protocol {
       PyObject_HEAD;
       void*                 __pyx_vtab;         // Cython vtab (subclass slot dispatch)
       allocator_protocol*   ap_header;          // protocol of the bound block
       uintptr_t             ap_binding_id;      // callback registration id
       size_t                ap_header_offset;   // byte offset of the subclass header field
       cpp_extra_dealloc_func cy_extra_dealloc_fn;  // armed __ccp_dealloc__ override
   } ccp_protocol;

The subclass's header field position is **free** — the bind functions
receive its address (``&self.header``) and store the computed byte offset,
so nothing is aligned by layout.

Bind / unbind contract
^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1

   * - Operation
     - Protocol & ref derived from
     - Incref / decref target
   * - ``c_ccp_bind(obj, &header)``
     - the header itself (block start)
     - the header
   * - ``c_ccp_bind_embedded(obj, &header, parent)``
     - ``parent`` (the parent block start)
     - the parent block start
   * - ``c_ccp_unbind(obj)``
     - the stored ``ap_header``
     - ``protocol->buf`` (never the field value)

Unbind is idempotent (already-unbound returns success) and always decrefs
the block start — an embedded header holds an interior pointer, and
decref'ing an interior pointer aborts under ``AP_ALLOC_VIGILANT``.

Dealloc pass
^^^^^^^^^^^^

Every bound wrapper holds one ``c_ap_incref`` while bound. When a block is
freed, ``c_ap_free`` fires ``AP_CALLBACK_EVENT_DEALLOC`` **before** its
``ref_count > 1`` check:

.. code-block:: text

   c_ap_free(header)
     ├─ invoke callbacks: AP_CALLBACK_EVENT_DEALLOC
     │    └─ per bound wrapper:
     │         ├─ unbind: unregister callback + decref (drops the binding ref)
     │         ├─ __ccp_dealloc__ hook (when overridden) — header still valid
     │         └─ null the wrapper's header field (via the stored byte offset)
     ├─ vigilant checks pass (ref_count back to the allocation's own 1)
     └─ reclaim the block

The adaptor snapshots the header offset before unbinding (unbind zeroes
the state), uses byte arithmetic, and guards a zero offset.

Guidance
--------

Apply the CCPType binding **per class**, only when reverse dealloc
invalidation is needed:

- instances can be created from an existing block (``c_from_header`` /
  fork / embedding), so views may outlive the owner, or
- the block can be freed by a path other than that wrapper's own
  ``__dealloc__`` while the wrapper is alive.

Do **not** use it when:

- init/dealloc is in the **hot loop** — callback registration and list
  mutations per construction cost; keep hot-loop wrappers plain (owner
  flag + NULL checks), or create them unbound (the binding, not the
  inheritance, is what costs);
- no reverse invalidation is needed — a single-owner class whose block is
  only freed by its own ``__dealloc__`` and is never adopted;
- teardown must reach **state beyond the wrapper** — reset extra fields
  with the ``__ccp_dealloc__`` override; register a custom
  ``ap_callback_func`` only for state outside the wrapper (cross-process
  registrations, non-wrapper callbacks).

Common mistakes
^^^^^^^^^^^^^^^

- Binding inside ``c_from_header`` — the variant is unknowable at adoption.
- ``ccp_bind`` on an interior header — use ``ccp_bind_embedded`` with the
  parent block start.
- Forgetting to bind after ``_new`` / adoption — no invalidation on free
  and an unbalanced ref count.
- Missing NULL guards on accessors — husks outlive owners.
- Arming the ``__ccp_dealloc__`` check in ``__cinit__`` — the subclass
  vtab is installed after the base ``tp_new`` returns.
